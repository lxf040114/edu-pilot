## 一、核心概念自测（参考答案）

1. 为什么中文 RAG 不能直接用 MiniLM 这类英文 embedding 模型？
   答：MiniLM（all-MiniLM-L6-v2）是英文模型，向量空间以英文语义为主；中文句子被按字
   编码后语义距离失真，检索排序不可信（实测「闭包」定义被排到第 5）。

2. BGE 系列做「检索」时为什么要给查询加指令前缀？
   答：BGE 训练时用「任务指令」区分文档编码和查询编码；查询侧加「为这个句子生成表示
   以用于检索相关文章：」能让查询向量进入「检索分布」，与文档向量对齐。不加会掉点。

3. Multi-Query 为什么能降低漏检率？
   答：学生口语（"闭包咋记住变量的？"）和教材书面语有语义鸿沟，单查询可能漏检。
   让 LLM 改写成多个不同表述，从多角度召回再合并去重，召回更全。代价是多次 LLM 调用、延迟增加。

4. 双塔（bi-encoder）和交叉编码（cross-encoder）的本质区别？
   答：双塔把 query 和 doc 各自独立编码后算余弦，快但看不到两者交互、排序只是近似；
   交叉编码把 (query, doc) 拼成一段一起喂给模型逐对打分，准但慢。所以召回用双塔、精排用交叉。

5. 为什么工业级 RAG 普遍用「召回 + 重排」两段式，而不是一步到位？
   答：cross-encoder 对全库逐对打分太慢（每对都要一次前向）；先 bi-encoder 快速召回
   top-k 候选，再用 cross-encoder 对少量候选精排，兼顾速度与精度。

## 三、踩坑记录

- chromadb 1.5.9 的 EmbeddingFunction 协议变了：需要同时实现 `name()`、`__call__(self, input)`、
  `embed_query()`、`embed_documents()` 四个方法（旧版只要 `__call__`）。缺一个就报不同的错。
- HuggingFace 国内直连下载模型会超时/极慢，必须设 `HF_ENDPOINT=https://hf-mirror.com` 走镜像。
- torch / transformers 等大依赖官方源下载极慢，用 pip 清华镜像（`-i https://pypi.tuna.tsinghua.edu.cn/simple`）。
