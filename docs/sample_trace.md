## 什么是闭包

教材里的定义是：**闭包是指一个函数，以及它「被定义时所在词法作用域」的组合。即使那个作用域已经执行结束，这个函数依然能访问并记住当时作用域里的变量。**

简单说：闭包 = 函数 + 它出生时的那个环境。

```python
def outer(x):
    def inner(y):
        return x + y   # inner 记住了 outer 的变量 x
    return inner

add5 = outer(5)        # outer 执行完毕，但 x=5 被 inner 记着
print(add5(3))         # 输出 8
```

`inner` 就是闭包，它带着 `x=5` 这个"行李"离开了 `outer`，之后照样能用。

## 为什么能记住外部变量

关键在于 **Python 的作用域是"词法作用域"（lexical scope）**，也叫静态作用域——一个函数能访问哪些变量，在**定义它的那一刻**就由代码的书写位置决定了，跟"在哪里被调用"无关。

具体机制是这样的：

1. **作用域链在定义时确定**：`inner` 定义在 `outer` 内部，所以 `inner` 的作用域链是 `inner 局部 → outer 局部 → 全局`。这条链是写代码时就固定下来的。
2. **变量被"捕获"而不是"复制"**：`inner` 里用到了 `x`，Python 会把 `x` 作为 `inner` 的一个**自由变量**（free variable）记录下来，指向 `outer` 的那个变量本身，而不是拷贝一份值。
3. **函数对象持有环境引用**：函数对象内部保存着对"定义时环境"的引用（`__closure__` 属性里存着这些被捕获的变量）。只要 `inner` 这个函数对象还活着，它引用的那些变量就不会被垃圾回收——所以 `outer` 执行完了，`x` 依然存在。

可以用 `__closure__` 亲眼验证：

```python
add5 = outer(5)
print(add5.__closure__)          # (<cell at 0x...: int object at 0x...>,)
print(add5.__closure__[0].cell_contents)   # 5
```

那个 `cell` 就是"装变量的格子"，`inner` 通过它间接访问 `x`。

## 顺带一提：为什么计数器要写 `nonlocal`

教材示例里：

```python
def make_counter():
    count = 0
    def inc():
        nonlocal count   # 声明 count 来自外层作用域
        count += 1
        return count
    return inc
```

因为 `count += 1` 是**赋值**操作，不加 `nonlocal` 的话 Python 会认为 `count` 是 `inc` 的局部变量，从而报 `UnboundLocalError`。`nonlocal` 明确告诉解释器："我要改的是外层那个 `count`"。

## 闭包的三个典型用途（教材总结）

- **数据私有化**：把变量藏在闭包里，外部无法直接修改，只能通过返回的函数间接操作。
- **工厂函数**：用一个函数生成多个"带不同初始状态"的函数，例如计数器。
- **回调函数**：事件处理、装饰器底层都依赖闭包保存上下文。

### 补充一点更严谨的表述

教材和面试里通常会把第二点说得更细一些，建议你记成：

> **递归 = 终止条件 + 递归表达式（把问题分解为规模更小的子问题，并向终止条件收敛）**

关键在"**向终止条件收敛**"这几个字。光"调用自己"还不够——如果每次调用问题规模没有变小，或者变小了却永远到不了终止条件，照样会无限递归。比如：

```python
def bad(n):
    if n == 0:
        return 0
    return bad(n + 1)   # 调用自己了，但离终止条件越来越远 → 栈溢出
```

所以判断一个递归写得对不对，可以问自己两个问题：
- **有没有出口？**（终止条件）
- **每次递归有没有更靠近出口？**（收敛性）
