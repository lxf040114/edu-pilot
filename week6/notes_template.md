# W6 学习笔记（Agent 入门）

> 已用真实运行数据填好（2026-08-31 跑 `demo_agent.py`）

## 一、核心概念自测（参考答案）

1. Agent 的本质 = 什么 + 什么 + 什么？
   答：**大模型 + 工具 + 循环**。大模型负责「决策」（调哪个工具、传什么参），工具负责「执行」，
   循环（ReAct）把两者串起来反复交替，直到模型给出最终答案。

2. ReAct 的「推理」和「行动」各指哪一步？
   答：推理 = 模型结合上下文决定调哪个工具、传什么参数（返回 tool_calls）；
   行动 = 你的代码执行工具、拿到结果，再把结果作为 tool 消息回传。

3. 工具为什么要有 JSON Schema，而不是直接把 Python 函数丢给模型？
   答：JSON Schema 是模型和代码之间的「接口契约」——模型靠 name/description/parameters 理解
   「什么时候该调、参数长什么样」，代码靠它校验参数。模型看不懂 Python 源码。

4. 为什么 assistant 消息的 tool_calls 要原样回传？
   答：协议要求。下一轮模型要「记得」自己上一轮调过什么工具、传了什么参数，必须把 assistant 的
   tool_calls 原样塞回历史，再附上 tool 结果，它才能接着推理（否则会重复调用或忘掉上下文）。

5. 循环为什么要设最大轮次（max_rounds）？
   答：防止死循环/失控——模型可能一直调工具、或参数一直错，max_rounds 兜底终止，保证请求一定返回。

## 二、实测：工具调用轨迹

运行命令：`.venv/Scripts/python.exe demo_agent.py`

| 用户问题 | 模型调用了哪些工具（按顺序） | 最终答案是否合理 |
|---|---|---|
| 算 (5-2)+(5-2)*3 | calculator('(5-2)+(5-2)*3') | ✅ =12，还写了计算过程 |
| 现在几点了 | get_current_time() | ✅ 星期一 21:43 |
| 闭包是什么 | search_knowledge_base ×3（「闭包」命中装饰器；「闭包 外部变量 记住」「闭包 定义 原理」均未命中） | ⚠️ 答案合理，但部分来自模型自身知识 |
| 先算 3 的平方，再问星期几 | calculator('3**2') + get_current_time()（**两个工具**） | ✅ 9 + 星期一 |

结论：ReAct 循环跑通，模型能自主决定调哪个工具、调几次、按什么顺序；
**多工具协同**（第 4 问）是相对 W2 单次调用最大的跃迁。

## 三、踩坑记录

- `search_knowledge_base` 是精确「包含匹配」，长查询（"闭包 外部变量 记住"）因字面不匹配而漏检，
  模型退而用自己的知识补全答案——这正是 W7 要换成向量 RAG 的原因（语义检索能召回「闭包.md」完整定义）。
